# Voice Bot — голосовой бот для звонков по скрипту

Серверный голосовой бот на **LiveKit Agents** (Python). Без веб-интерфейса —
чистый воркер, который поднимается отдельным контейнером и ведёт разговор по
сценарию.

Стек одной строкой: **LiveKit** (транспорт звука) + **OpenAI** (распознавание
речи и «мозг») + **ElevenLabs** (голос). Логика диалога — детерминированная,
живёт в коде; тексты сценария — в JSON.

---

## Как это устроено

```
Клиент ──звук──▶ LiveKit ──▶ Агент (воркер) ──▶ голос обратно клиенту
                              ├─ STT   речь → текст      (OpenAI)
                              ├─ LLM   формулирует ответ (OpenAI)
                              ├─ TTS   текст → голос      (ElevenLabs)
                              └─ VAD   ловит конец реплики (Silero)
```

- **LiveKit-сервер** — «труба», возит звук. Поднимается отдельно (docker).
- **Агент** — этот проект. Отдельный процесс-воркер, подключается к серверу.
- STT / TTS / VAD — готовые плагины, подключаются одной строкой (`session.py`).
- Свой код — только сценарий и системный промпт.

## Структура

```
src/voice_bot/
├── config.py            # настройки из окружения (Pydantic Settings)
├── logging_setup.py     # единый формат логов
├── agent/
│   ├── main.py          # точка входа воркера (dev / console / start)
│   ├── session.py       # сборка сессии из плагинов (STT+LLM+TTS+VAD)
│   └── script_agent.py  # агент со сценарным промптом
└── scenario/
    ├── models.py        # модель сценария (Pydantic)
    ├── loader.py        # загрузка сценария из JSON
    ├── prompt.py        # сборка системного промпта из сценария
    └── data/
        └── vector_ru.json   # сам сценарий (данные, не код)
tests/                   # тесты сценария и настроек (без сети и без ключей)
```

## Что нужно для запуска

Три ключа от внешних ИИ-сервисов (остальное поднимаешь сам):

- `OPENAI_API_KEY` — распознавание речи + «мозг»;
- `ELEVENLABS_API_KEY` — голос;
- `ELEVENLABS_VOICE_ID` — ID записанного голоса компании.

LiveKit локально бесплатный — ключи для него уже прописаны в `docker-compose.yml`
и `.env.example` (`devkey` / `secret`).

## Быстрый старт (локально, без docker)

Самый быстрый способ услышать бота — консольный режим: агент запускается в
терминале и слушает микрофон. Нужны только три ключа ИИ.

```bash
cp .env.example .env        # вписать OPENAI_API_KEY, ELEVENLABS_API_KEY, ELEVENLABS_VOICE_ID
make install                # поставить зависимости
make download-files         # разово скачать веса моделей (иначе console/dev падают на turn-detector)
make console                # поговорить с ботом прямо в терминале
```

> Список доступных подкоманд воркера: `python -m voice_bot.agent.main --help`.
> В консольном режиме LiveKit-сервер не нужен.

## Запуск в контейнерах (сервер + бот)

```bash
cp .env.example .env        # вписать три ключа ИИ
make up                     # поднимет LiveKit-сервер и воркер
```

Воркер зарегистрируется на сервере (`registered worker` в логах) и будет ждать
звонков. Чтобы завести живой звонок в этом режиме, нужен клиент, который зайдёт
в комнату и вызовет агента, — это следующий шаг (подключение фронта/телефонии).

## Разработка

```bash
make lint      # проверка кода (ruff)
make format    # автоформат + починка импортов
make test      # тесты
```

Правила кода: явные типы, читаемые имена, async-I/O, **русские докстринги**,
бизнес-логика вне точек входа, данные сценария отдельно от кода.

## Куда расти (заложено в структуру)

1. **Детерминированный автомат по шагам** (LangGraph) — жёсткий порядок
   вопросов, ветвления и дословные блоки вместо «модель старается».
2. **Классификатор ответа** — мутный ответ клиента → чистое значение шага.
3. **Кэш аудио** — заранее печём длинные дословные фразы, чтобы не ждать синтез.
4. **Понижение задержки** — заменить связку STT+LLM на OpenAI Realtime
   (режим «только текст»), не трогая TTS.
5. **Отчёт/CRM** — отдельный фоновой процесс, не блокирующий речь.
6. **FastAPI-обвязка** — эндпоинт выдачи токена, вебхуки, админка.
